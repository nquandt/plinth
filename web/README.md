# Plinth web host

Runs the SAME `.plnt` package and the SAME runtime core file the desktop
host uses, directly in a browser. No bundler, no build step, no npm
dependency: plain ES modules (SPEC.md §18.3, the "browse mode" side-module
model — no static linking happens in the browser).

## Try it: the web App Hub

The simplest way is the web App Hub (`docs/web-hub.md`): one command builds
the example apps into a registry and serves the registry, a landing page
that lists the apps, and this web host on one origin.

```sh
bash scripts/web-hub-demo.sh        # then open http://localhost:8787/
```

For your own apps: `plinth registry build <folder> --with-core`, then
`plinth registry serve <folder> --web [--port N]`. The web files are
embedded in the `plinth` binary, so the server works from any folder. To
test from a phone or another laptop, use a Cloudflare quick tunnel
(`cloudflared tunnel --url http://127.0.0.1:8787`); the tunnel URL is
public, see `docs/web-hub.md` §2.

## Try it: one app, any static server

```sh
cargo build -p plinth-cli
target/debug/plinth.exe build examples/counter      # writes examples/counter/dist/counter.plnt
target/debug/plinth.exe core export target/core.wasm # the runtime core, as a plain core wasm module

npx -y http-server . -p 8080
# then open:
# http://localhost:8080/web/index.html?app=../examples/counter/dist/counter.plnt&core=../target/core.wasm
```

Any static file server works (the browser needs `fetch` of `.plnt` and
`.wasm`, so `file://` will not do).

## Files

| File | What |
|---|---|
| `plinth-web.js` | Loads a core and an app module and links them side-module style: grows the core's exported table by the app's table import minimum, then instantiates `app.wasm` with `{ "plinth-rt": { ...rt exports without the prefix, memory, table, table_base } }`. Implements the host imports (`ui`, `dev`, `time`, `store`, `clipboard`, `dialog`, `net`, `hub`). No DOM code, so it is also what the Node tests exercise. |
| `protocol.js` | The op buffer / event wire format (SPEC.md §8.2, §8.4) in JS, byte-compatible with `crates/plinth-protocol`. Hand-written, not generated; keep it in sync by hand if the wire format changes. |
| `zip.js` | A tiny read-only zip reader for `.plnt` packages (stored or deflated entries), using the standard `DecompressionStream("deflate-raw")` (no dependency). |
| `ui-api.js` | GENERATED by `scripts/gen-web-ids.mjs` from `wit/plinth/ui-api.toml`. Re-run the script after the id table changes. |
| `dom-renderer.js` | The only DOM-specific file of the host: a semantic tree built from the op stream (`Tree`, which also records what each commit changed), and a renderer for the UI API 1.5 controls (plain semantic HTML: `<button>`, `<input>`, `<dialog>`, headings, lists, inline SVG charts), the nav shell, stack navigation, and `<Image>` assets from the package. The renderer keeps one element per node and updates it in place (SPEC.md M5): the focus, the caret, text selection and hover stay across commits, and a change to one row of 10,000 touches only that row. |
| `style.css` | The runtime-owned look (SPEC.md §3: apps declare intent; the runtime owns layout, spacing, color). Light and dark follow `prefers-color-scheme`. |
| `index.html` | `index.html?app=<url of .plnt>&core=<url of core.wasm>[&back=hub.html#…]`. With `back`, a link above the app goes back to the web App Hub. |
| `hub.html`, `hub.js` | The web App Hub page (`docs/web-hub.md`): the app list with search, the app page with the capability label, and Open. |
| `hub-logic.js` | The web App Hub's logic with no DOM: registry reading, search, the browser support of each capability, the core choice, the Open URL. |
| `test/run-*.mjs` | Node 22 tests (same `WebAssembly` API as the browser) that exercise `plinth-web.js`, `protocol.js` and `hub-logic.js` directly, with no DOM. `scripts/ci-local.sh` runs all of them except `run-a11y.mjs`. |
| `test/run-a11y.mjs` | By hand (needs Edge and the axe-core CDN): axe-core on 5 apps and on the web App Hub in headless Edge, over the DevTools protocol, plus the in-place renderer checks (typing, a held click during timer ticks, hover and text selection across ticks, a TextArea selection across a commit, row identity in todo, and one changed row of big-list's 10,000 with its time). `--hub-only` checks only the hub; `--typing-only` runs only the renderer checks; `A11Y_SHOTS=<folder>` saves screenshots of the hub. |

## Host APIs in the browser

| API | State |
|---|---|
| `ui`, `dev` | Work. |
| `time` | Works: `now`, `monotonic-now`, the time zone offset, and timers (`setTimeout`/`setInterval`; each fired timer is a `timer` event). |
| `store` (kv) | Works, backed by `localStorage` with the app id as a key prefix, when the manifest declares `store.kv` (else `denied(undeclared)`). All apps on one origin share the site's storage. |
| `clipboard` | Works with `navigator.clipboard`. The interface is synchronous and the browser API is not: `writeText` is fire-and-forget; `readText` returns the last known value and starts an async read for the next call, so the first read can return nothing. The browser can ask for permission, and it gives the clipboard only to a secure page (HTTPS or `localhost`). |
| `dialog` | Works with the browser's own `alert`/`confirm`/`prompt`; the answer is a `completion` event. |
| `net` | Works with `fetch`, checked against the manifest's `net:<host>`/`net:*`/`net.local`. The target server must allow CORS. |
| `hub` | Not supported: every call is `denied(unsupported)` (the Hub UI needs the desktop host). |

## Not done yet

- **No static linking in the browser** (by design, SPEC.md §18.3): each app
  instantiation grows the table and wires imports again. Fine for one app;
  not tested with many apps that share one core instance.
- **One origin for all apps**: `docs/HUB.md` §7.6 asks for one origin for
  each app, so that storage stays separate.
- **No consent in the browser**: the web host gives each declared capability
  that it supports; the web App Hub only shows the label.
- No parity tests between the HTML a11y output and the desktop AccessKit
  tree (axe-core checks the HTML).
